Códigos de MATLAB y Simulink

Cómo están organizados, cómo se corren y cómo se mejoran

Todos los códigos viven en la carpeta codigo/ del repositorio. Son la misma fuente que se ve en las notas en PDF y en estas páginas: los bloques de código se extraen de los archivos al compilar, de modo que nunca se desincronizan.

Primeros pasos

>> cd ruta/al/repositorio/codigo
>> iniciarCurso            % agrega comun/ y todos los capítulos al path
>> C1_Ej1_RespuestaSenoidal

Se necesita Control System Toolbox (y Simulink para los crearModelo_*.m).

Convenciones de los scripts

Cada script empieza con un encabezado como este:

%% C3_Ej3_AjusteGanancia -- Notas: sección 10.10 (diseño ajustando la ganancia; adaptado de Nise)
% Gp(s) = 1/(s(s+20)(s+100)), Gc = Kc, meta: %OS = 20 %
% ESPERADO  zeta = 0.456 -> PM = 48.15° -> fase objetivo -131.85° en 13.56 rad/s
%           |2000 Gp| = -24.36 dB  ->  Kc = 33 056;  %OS logrado 19.9 %
clear; close all; clc;
if ~exist('bodeAsintotico', 'file'), addpath(fullfile(fileparts(mfilename('fullpath')), '..', '..', 'comun')); end

G0   = zpk([], [0 -20 -100], 1);
zeta = zetaDeOS(0.20)                                % 0.456
PMd  = pmDeZeta(zeta)                                % 48.15°
Fdes = -180 + PMd                                    % -131.85°
wd   = fzero(@(w) faseEn(G0, w) - Fdes, [1 30])      % 13.56 rad/s (la ganancia NO cambia la fase)
Kc   = 1/abs(evalfr(G0, 1j*wd))                      % 33 056: |Kc G0(j wd)| = 1 = 0 dB

L = Kc*G0;
margenesTabla(L, 'Kc ajustado');
stepinfo(feedback(L, 1))
fig = estiloFigura(1000, 600);
subplot(1,2,1); margin(L); grid on;
subplot(1,2,2); step(feedback(L, 1), 0.8); grid on; title(sprintf('K_c = %.0f', Kc));
exportgraphics(fig, 'C3_ajuste_ganancia.png', 'Resolution', 200);

%% El precio: kv = Kc/2000 = 16.5. Si se exige kv = 40 con la ganancia sola:
L40 = 80000*G0;  margenesTabla(L40, 'Kc = 80000 (kv=40)');   % PM = 25.4°
stepinfo(feedback(L40, 1))                                   % %OS ~ 49 %: hace falta un compensador
  • QUÉ HACE / OBSERVE / ESPERADO / EXPLORE: para qué sirve, qué mirar, qué números deben salir y qué cambiar para aprender más.
  • Los fragmentos que aparecen en las notas están entre % [ini:nombre] y % [fin:nombre].
  • Los modelos de Simulink se construyen por código (crearModelo_*.m): no hay .slx binarios en el repositorio y cualquiera puede ver qué bloques tiene cada modelo.
  • Los nombres de variables siguen la notación del curso: Gp, Gc, Kc, PM, wPM, Mr, wr…

¿Quiere mejorar un código?

  1. Haga el cambio en el archivo de codigo/.
  2. Corra verificarCap10 (o el verificarCapNN del capítulo): si algún número de las notas deja de coincidir, lo dirá.
  3. Recompile las notas y el sitio: los fragmentos se actualizan solos.
  4. Si encontró un error, abra un issue en el repositorio.

¿Y si no tengo MATLAB?

Los cálculos (no las figuras ni los videos) corren también en GNU Octave con el paquete control (pkg load control), salvo allmargin, pidtune y VideoWriter, usando las funciones de reemplazo de herramientas/octave_shims/ (por ejemplo, evalfr). Además, todos los números del capítulo 10 se verificaron de forma independiente en Python (herramientas/cap10_numeros.py).
